Qué cambió

Problema

Las skills compartidas buscaban helpers mediante PLUGIN_ROOT o CLAUDE_PLUGIN_ROOT. Codex puede cargar una skill sin definir ninguna de esas variables, por lo que comandos como status, setup y review-watch podían construir una ruta inválida terminada en /scripts. Véase skills/review-watch/SKILL.md:16.

Causa raíz

Los recursos ejecutables estaban centralizados en la raíz del paquete, mientras que el runtime solo garantiza la ubicación de la skill cargada. La instrucción no usaba la ruta física de SKILL.md como punto de partida. Véase skills/setup/SKILL.md:23.

Solución

Cada helper determinístico vive ahora dentro de su skill. Las instrucciones resuelven SKILL_DIR desde el archivo cargado y derivan PACKAGE_ROOT solo cuando necesitan acceder al paquete completo. Los scripts raíz quedaron como wrappers compatibles. Véase scripts/review-watch.sh:4 y skills/setup/SKILL.md:29.

Verificación

Validado en ambos runtimes. Se probaron paths con espacios, variables eliminadas, wrappers, helpers skill-locales, fallback de Claude, descubrimiento local de Codex y una instalación aislada del plugin. El conjunto se ejecuta desde scripts/validate.sh:243.

Riesgo y entrega

Riesgo principal

Una ruta mal derivada podría ejecutar el helper equivocado o impedir una skill. Se mitiga verificando archivos físicos, probando paths con espacios y rechazando fallbacks silenciosos. Véase scripts/test-skill-resource-paths.sh:1.

Rollout

La versión 2.5.2 puede cargarse como plugin o desde .agents/skills. No deben habilitarse ambos modos simultáneamente porque aparecerían skills duplicadas.

Rollback

Reinstalar 2.5.1 o revertir los dos commits del PR. Los wrappers raíz conservan las rutas de integración anteriores.
