## Design Context

### Users

The primary audience is developers evaluating or using Git Workflow from Claude Code or Codex. They arrive with a concrete job: understand what the project automates, confirm that it works in their host, install it safely, and find an exact command or operational reference without reading the repository end to end. The documentation must support both a two-minute evaluation and a focused implementation session.

### Brand Personality

Editorial, technical, and assured. The experience should feel like a carefully edited engineering field guide: direct enough for daily use, rigorous enough to trust with pull requests and releases, and human enough to make complex workflows approachable. It should evoke confidence, control, and curiosity without hype.

### Aesthetic Direction

Use an editorial publication language built from warm paper surfaces, ink-tinted neutrals, ruled dividers, marginal annotations, and one signal-orange accent. Pair an expressive serif display face with a restrained humanist sans and use monospace only for commands and technical labels. Support equally intentional light and dark themes. Favor asymmetric compositions, diagrams, real product evidence, and strong typographic rhythm over card grids, glossy effects, gradients, or generic developer-dashboard styling.

The site is a future-facing Agent Tooling hub, with Git Workflow as its first and only product in v1. It may share a quiet visual signature with navarrolajous.com, but it must remain a distinct open-source documentation property rather than an extension of the personal portfolio.

### Design Principles

1. **Lead with the developer's outcome.** Explain the value and the next command before exposing the full feature surface.
2. **Evidence over decoration.** Use real notifications, real decision briefs, and accurate workflow diagrams as the visual language.
3. **One source, many readers.** Present the same canonical documentation clearly to humans, search engines, and coding agents without hand-maintained copies.
4. **Editorial hierarchy, operational precision.** Generous rhythm and distinctive typography must coexist with copy-paste-safe commands and unambiguous host labels.
5. **Fast and inclusive by default.** No remote fonts, analytics, or ornamental JavaScript; meet WCAG 2.2 AA, preserve zoom and reduced motion, and adapt rather than merely shrink on small screens.
